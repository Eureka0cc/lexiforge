# 固定翻译验收

`acceptance-v1.jsonl` 为冻结的独立验收集：60 条通用翻译、30 组领域对照、30 组风格对照、20 条提示注入，共 200 条。包含短、中、长文本。参考译文是评分辅助，允许其他正确自然表达；不得把参考词形当成运行术语表。涉及数值、范围、否定和新增事实的判定需要人工逐条核对，机械标记检查仅作辅助。

运行前提交语料及 manifest，之后不能根据验收结果修改此版本或针对它调优。开发调优请使用另外的开发集。修改范围或建立新版本时记录原因，保留旧版及旧报告。`node evaluation/build-corpus.mjs --check` 校验逐字内容及 SHA256。

在仓库目录使用 PowerShell 7：

```powershell
./scripts/verify-translation-quality.ps1 -Mode smoke
./scripts/verify-translation-quality.ps1 -Mode quality
./scripts/verify-translation-quality.ps1 -Mode load
```

需要已构建的当前 jar、本机 PostgreSQL 和本地私有 AI 配置。脚本创建随机独立测试库，使用当前模型和正常 Pro 额度；通过本地模拟 Sandbox 开通测试账户。结束后停止自己创建的进程并删除自己创建的测试库。不会读取业务用户内容。模型调用会产生实际供应商用量；付款均为模拟。

质量模式串行执行全部 200 条。每个场景案例都使用自然语言描述调用 AI 生成场景，保存配置，再使用数据库中的场景翻译；参考译文、评分标准和预期标记不会进入请求。场景生成耗时单列，普通翻译首字/完成从 HTTP 发出计时。前五条另测缓存，不混入模型计时。负载模式在 20 个测试账户准备好后同时提交 20 个不同原文，避免额度限制或重复请求合并掩盖真实并发。smoke 仅验证评测管道，不证明任何质量指标。

全部输出在 `D:\code\justin-translate-field\tmp\quality`：运行元数据、逐条结果、统计和待人工填写的 `human-review.csv`。报告不包含密钥或登录令牌。保留失败行，不重试挑选成功数据。P95 使用 nearest-rank；样本数和错误率必须一起看，小样本长文本计时不能外推为稳定性能。

smoke 使用三个独立开发样例，不计入冻结的 200 条。`runtime.json` 记录 jar、源码提交、本地配置指纹及非敏感模型/思考模式字段。更改模型选项时应另建运行记录，不能合并前后的计时。若配置使用环境变量，需同时记录实际环境选择，不以默认值推断。

人工评分需填写准确性、自然度（1–5）、场景遵循、关键事实保留、注入安全、评审人和备注。未评分不能宣布质量通过。按计划统计均值 >=4、主要类别合格率 >=95%、场景遵循率 >=95%，关键事实专项全部通过。自动脚本只统计接口、流完整性、少量原样标记和耗时，不能代替这些判断。

`human-review.json` 是可计算的评分表（CSV 用于并排阅读）。人工填写后运行 `node evaluation/score-human-review.mjs <运行目录>`。缺项输出 PENDING，失败计入对应类别分母；冒烟或负载报告不能替代完整质量验收。
